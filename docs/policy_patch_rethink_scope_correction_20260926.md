# LEAD-POLICY-14: scope and empty-diagnostic correction for PATCH/RETHINK

**Coordinating scientific lead, 26 September 2026, 16:16 UTC. Decision: repair the provisional action definition; HOLD every model stage.** This is a source-only review of [LEAD-POLICY-13](policy_patch_rethink_action_candidate_20260926.md), not a result, protocol freeze, or authorization to collect.

The two recipes share the same visible history, but they do **not** differ only in a latent “patch versus rethink mechanism.” The last instruction differs in wording, length, and permitted use of the prior answer: `PATCH` says to preserve correct behavior, whereas `RETHINK` says to use the prior answer only to avoid witnessed errors. A valid randomized comparison at an identical prefix would target the **total effect of assigning the two entire rendered instructions** on the prespecified outcome, conditional on a well-defined assignment, consistent execution and complete or prespecified handling of missing outcomes. It would not isolate which phrase, cognitive strategy, or amount of previous-answer reuse caused a difference. Record token and runtime consequences separately. Conditional ranking would be a property of these frozen recipes on the supported history distribution, not evidence that a general patching mechanism works.

The provisional `RETHINK` text in LEAD-POLICY-13 refers to “the original task and public diagnostic” even when the frozen public diagnostic contains no failure. For a well-defined action on both public-pass and public-fail histories, amend that sentence to: “Re-derive a solution from the original task and public diagnostic, **if any**.” The rest of the provisional text stays unchanged. This is a **prospective action-definition repair** before any assignment; it does not relabel or correct E12/E13a outcomes. At protocol freeze, specify whether a public-pass history deterministically takes `STOP` or is included in recipe randomization. Do not silently condition the analysis on post-assignment assessability or select the better-looking support after seeing outcomes.

The original estimand remains the value of a history-conditional same-prefix next-prompt policy against a competent development-selected fixed recipe. This amended class changes the **treatment support** relative to E12 N1/S1, so old grades cannot train or validate `PATCH` or `RETHINK`. Before model calls, freeze exact rendered bytes for both public-status cases, the common terminal contract, source and family frame, assignment probabilities, all-assigned endpoint, comparator and selector rules, useful-gain/precision/futility rules, hashes and versions, and a numerical local cap with a resource lease. No worker job, model call, token, program execution, download or paid cost follows from this note. The 58% planning rubric is unchanged; prompt efficacy and independent policy validation remain unestablished, and the project is not submission-ready.
