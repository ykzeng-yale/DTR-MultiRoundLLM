# Private-test instrument feasibility, before any model collection

Codex scientific lead,30 September2026. Prospective source-data experiment only; no task adoption, reference validity or policy efficacy.

Question: does the pinned proposed source provide correctly aligned, structurally decodable private standard-input test batteries within the declared observer's bounds, and how much of that battery duplicates public examples? A public source roster alone cannot answer this. Missing, mixed-interface, very large, duplicated or contradictory cases must be retained and ruled before constructing an outcome instrument. This inquiry is uniform over all1,055 source rows; no receiver performance is consulted.

The assignment is the complete `release_v6` converted Parquet snapshot at revision `25d8cb8f0db2efe1b589941eb8c26a219850d4d2`, joined in exact shard/row order to the already acquired public projection. It reads only `platform`, `question_id` and `private_test_cases`. Every row remains in the journal, including functional-interface rows outside the stdio proposal. Other column chunks, including metadata or any reference, are refused. Footer metadata may necessarily contain other-column statistics. Range response bytes and hashes are retained; whole-shard LFS digests are not claimed verified.

The official parser describes direct JSON or base64/zlib wrapped pickled JSON strings ([publisher parser](https://raw.githubusercontent.com/LiveCodeBench/LiveCodeBench/main/lcb_runner/benchmarks/code_generation.py)). We do **not** invoke that parser, remote dataset code, `pickle.loads` or an Unpickler. The versioned reader accepts direct JSON, base64/zlib JSON or a narrowly whitelisted opcode stream containing exactly one Unicode literal string plus framing/memo/STOP. It inspects opcodes without constructing arbitrary objects. Executable, container, retrieval or unsupported opcodes are refusals retained as unresolved rows. Inflated/encoded lengths, case counts, duplicate JSON keys, exact case schema and trailing compressed/pickle data are checked. Decodability does not establish correctness of expected answers.

Raw private inputs and expected outputs remain in ignored acquisition storage; they are not printed, committed, passed to policies or included in review messages. The result ledger exports hashes, alignment, encoding and aggregate type/count/size/duplicate/conflict flags only. Public/private exact case overlap and input overlap are recorded separately. Different expectations for one identical input nominate semantic review; they do not automatically establish test error for a multivalued task. No task, benchmark, candidate or reference code executes. No test outcome is generated.

Finite envelope: one trusted data-reader CPU;3,600CPU seconds and7,200wall seconds;5GiB fetched response bodies,6GiB retained artifacts;8MiB maximum range request;128MiB encoded field,256MiB inflated field and100,000cases per row. Require10GiB initially free owned storage and retain a2GiB free-space floor between shards. The existing Python3.12.13/PyArrow19.0.1 reader is pinned and no package is installed. Disk-backed range caching avoids retaining all shards in RAM; logical range allocation is capped at1,280MiB. All already acquired footer hashes/lengths are pinned before decoding (largest11,323bytes); compressed/uncompressed column sizes and row-group shapes are also pinned. There is a16GiB best-effort address-space limit and a measured peak-RSS refusal. These are **not** a certified hard MacRSS reservation: Arrow may allocate column/page buffers before encoded-field, JSON/case and measured-RSS checks. Those checks are post-Arrow refusals, not an adversarial memory-sandbox proof. Paid services/model calls/GPU allocations are zero.

Independent internal review identified four prelaunch corrections. Retained bytes are now bounded before writes by the5GiB payload cap plus at most1,024range requests with2,048-byte receipts, a20MiB row journal and separately reserved1MiB plan/summary files; this serialized allowance is below6GiB. Footer length/hash is checked before joining or decoding, not afterward. Expected stdout size at exactly65,536bytes is flagged as saturation, matching the prospective observer. Global CPU/wall handlers are not converted into row decoder failures; a final budget check precedes COMPLETED. Hard termination can still leave only a flushed prefix, which must be reconciled without restarting.

Preflight refusal is terminal before network. A cap, source drift or transport failure preserves the actual prefix and unattempted count; it does not authorize a replacement run. A row decoder failure remains unresolved, with a fixed safe failure tag rather than private text. The frozen plan binds the public projection, both reader source files, source revision, exact projection, runtime and resource limits. Raw data are not a release to candidate execution. Fresh containment qualification, source-backed output rules, reference/wrong-control validation, family/exposure admission and full development/evaluation freeze remain necessary.

The outcome of this inquiry decides whether the proposed standard-input instrument is feasible as currently bounded, whether a clearly versioned instrument proposal is needed, or whether the source path should close. Neither accepting only convenient tasks nor silently expanding input/time bounds is authorized by the result. Source-backed scope exclusions must be outcome-blind and every original source row remains accounted for. Readiness remains60%,delta0; actual learned-policy fit and independent quality/cost evaluation are still absent.
