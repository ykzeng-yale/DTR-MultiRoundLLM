## 1. The target is an instruction rule, not two constant strings

The estimand is the **finite-history contrast between a fixed neutral instruction and a
public-diagnostic-dependent instruction rule**. NEUTRAL is the constant `diagnostic.N_INSTRUCTION`. DIRECTED
is **not** a constant string: it is the rule `diagnostic.select_s1(diag)`, which chooses among three predeclared
strings from the root's **public** diagnostic statuses (a recorded failure, incomplete information, or all
public examples passing). For fixed realized histories `H = (h_1..h_10)`:

`theta_H = (1/10) sum_g [ E(Y_D | h_g, frozen receiver law) - E(Y_N | h_g, frozen receiver law) ]`

Its all-assigned six-draw sample contrast is a different object and does not become `theta_H` by definition.

This does **not** validate a learned personalized policy, and it says nothing about longitudinal policy value.
It is one development contrast at ten fixed, already-exposed histories.

## 2. Draws and conditional means

Relating the draws to the conditional means `E(Y | h_g, ...)` requires the **declared receiver-sampling law**,
together with consistency/state restoration and no interference. **Independence of labelled seeds is not
sufficient**: deterministic seeds are reproducibility settings, and non-colliding seed values do not establish
that the receiver's draws are independent samples from the declared law.

## 3. Hoeffding — the blanket "vacuous" claim is withdrawn

v3 said that at these sizes "a `[-1,1]`-bounded distribution-free radius is in any case vacuous". **That is
withdrawn.** Under the hypothetical assumption of ten independent, equally weighted contrasts bounded in
`[-1, 1]`, the usual two-sided 95% radius is

`sqrt(2 * log(40) / 10) = 0.8589`

which is wide but not vacuous. This arithmetic **neither establishes** the independence and weighting
assumptions **nor releases** an interval. The development stage stays descriptive: no normal interval, no
Hoeffding interval, no efficacy claim and no futility claim.

## 4. The extractor, described exactly

v3 described `grade.extract_code` as returning raw text in the non-matching fenced case ("otherwise raw
text"). **That is wrong.** The frozen rule is:

- if **no** triple-backtick marker occurs anywhere, it returns the raw text (stripped);
- if **any** marker occurs, it requires exactly two markers forming exactly one block (optionally labelled
  `python`/`py`), and returns that block; **any other fenced form — ambiguous or malformed — raises and is
  rejected**.

So an unfenced answer is scored like a fenced one, and malformed fencing is rejected rather than passed through.
The scorer is unchanged; `terminal-output-contract-v2` remains a common intervention instruction and is never an
additional pass/fail rule.

## 5. Cost figures are an analogue scenario, not a bound

The execution contract's prompt-token figure for continuations (`>= ~51,200`, 120 × 426.8) was labelled a
"lower" estimate. **It is not a lower bound.** 426.8 is E13a's R1-arm mean prompt length on different tasks and
different answers, so this is an **analogue-based cost scenario** only. E14 prefixes retain the previous answer
and add the terminal instruction, and these tasks differ, so realized prompt length can fall on either side of
it. The same applies to every completion-token figure borrowed from E13a.
