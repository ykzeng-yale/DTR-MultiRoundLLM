# Saved STOP records: stage-residual availability check

**Lead source audit, 2026-09-23T18:36:26Z.** This is a read-only check of the closed 96-dataset E0 STOP archive, not a new diagnostic result. It uses no simulation draws, fits, model calls, program executions or paid services.

The immutable journal contains 96 `prepared` events and 1,152 terminal `variant` events (twelve variants per dataset). Each terminal event records root-level plug-in and DR means, aggregate fold/stage support counts, and timing. Each `dataset_*.npz` contains logged task IDs, three-stage states/actions/behavior probabilities/eligibility, final outcome, and fold assignments. The inspected `dataset_000.npz` has 9,200 trajectories, 230 roots and no fitted nuisance arrays. The journal event schema likewise has no per-trajectory, per-stage Q predictions, residuals, or stage-specific DR correction terms. Existing saved-root results can check total DR-minus-plug-in corrections and exposure to large weights, but cannot uniquely attribute those corrections to a stage or to nuisance prediction versus weighted residual from these fields alone. Aggregate support counts do not restore the missing values.

**Decision: hold the proposed exact stagewise residual/correction decomposition.** Its necessary next input is a versioned, provenance-bound record of held-out stage-level nuisance predictions and score increments, or an explicitly authorized bounded offline replay/refit of the frozen source with separate output and validation. Neither exists in the inspected immutable journal. A replay would be a new analysis with its own resource allowance and evidence label; it would not repair the original intervals or add prompt efficacy evidence. The original 96-dataset results and all twelve variants remain unchanged.

No saved values or outputs were changed. This is a source-availability judgment, not an independent observation of the old execution process.
