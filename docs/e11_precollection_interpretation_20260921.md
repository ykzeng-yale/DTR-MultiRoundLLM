# E11 interpretation before collection

This lead-owned interpretation guide records how to read the existing frozen development contrasts. It changes no intervention, endpoint, sample, analysis, stopping rule or release condition. It was written while MRL-13 was acknowledged but blocked on receiver scheduling, before any E11 outcomes were delivered.

| Observed pattern | Supported reading and next discriminating action | Claim not supported |
|---|---|---|
| S1 exceeds N1 with identical public diagnostic bytes | Descriptive evidence that the directed instruction helped on the observed development roots. Inspect every paired root, missingness and costs; retain the frozen comparison. | General prompt benefit, policy improvement, or an identified single-conversation individual effect. |
| N1 exceeds N0 but S1 does not exceed N1 | Consistent with benefit from the diagnostic-exposure package rather than additional directed wording in this sample. Inspect initial public/private status and all per-root contrasts. | That the directed strategy works, or that a specific diagnostic mechanism is proven. |
| S1 and N1 are similar, including apparent ties | Preserve the result as descriptive. Two continuations per root and one unresolved family cannot establish equivalence or population futility. | DTR identification is false, or no history-dependent policy could help. |
| Continuation improves initially wrong outputs but damages initially correct outputs | Report both denominators and outcomes, with unknown initial grades separate. A future selector would need observable decision-time information and independent evaluation. | A selector that can use private initial correctness at deployment. |
| R1 exceeds N1 | Descriptive evidence for the declared context-removal package; it retains diagnostics about the earlier answer. Compare token costs too. | Independent task-only resampling or an equal-token comparator. |
| Some outputs or grades are missing | Show assigned counts, reasons, complete-pair results and the existing all-assigned completion bounds. Reconcile transport, reference/control and grading failures before outcome claims. | That complete cases represent all assigned roots, or that completion bounds are confidence intervals. |
| Large apparent differences vary by root | Candidate heterogeneity for future study. Keep full root vectors; learn only on declared development data and freeze a policy before independent evaluation. | Achievable oracle performance from choosing each root's best observed branch. |

S1–N1 remains primary. N1–N0, S0–N0, R1–N1 and every continuation-versus-STOP contrast remain visible regardless of sign. The initial public-status by private-STOP-status table is descriptive; final public-pass/private-fail rates are not measured by this run. No confidence intervals or significance tests are added for these seven reused roots with unresolved family independence.

Report receiver calls, prompt/completion tokens, shared diagnostic starts/seconds and private grading costs separately. An instruction advantage with higher tokens is not an equal-cost advantage. Unmeasured costs remain unknown. No new utility conversion or winning threshold is selected after inspecting outcomes. The future 5-percentage-point useful-gain target does not turn this development run into a powered confirmatory test.

After the run, independently reconcile immutable records and the prespecified contrasts before any source repair or design change. A genuine runtime/measurement defect is repaired against its stated contract while preserving the original record; a different information package, receiver, population or endpoint is a new version and scientific target. Neither favorable nor unfavorable development results release generator expansion or independent policy collection automatically.
