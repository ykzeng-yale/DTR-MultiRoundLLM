## Why another N1/S1 format pass is not the next experiment

The frozen E12 renderer (`experiments/landmark/diagnostic.py`, SHA256 `2a98bccf20cf3fa068790b488be8df4347387ae5ffb1bd7b1bd8b9d49d3a72b2`) gives N1 and S1 the same initial answer and canonical public diagnostic. N1 scored 20/28 and S1 19/28 across 14 reused development roots. The later static E12 description (SHA256 `1561bbc7a9b7670916416e7cbbf872386db8b2996748d65e0b834a35cba66a69`) found seven S1 multi-block outputs, all among ten S1 continuations on public-fail roots; this is an association under the frozen complete-answer endpoint, not identified formatting mediation or recoverable semantic success. The original base prompt already required one answer. A stronger final-output instruction is a **new treatment**, not a correction to the negative E12 result.

The historical E14 same-prefix proposal already applied one common final-output instruction to both neutral and directed arms; its corrected `terminal-output-contract-v2` withdrew an unenforceable fence requirement after a source/static validation (SHA256 `e02ac933e2734e93f1573aa218907396101b6ec38b0c8638e9c5c245fd851ebb`). Private-suite compatibility was **not** validated by that check. E14 N1/S1 collection remains NO-GO because this narrow class lacks a demonstrated decision-worthy selector and independent-family policy contract. Repackaging that proposal as a new format pilot would repeat the same bottleneck.

## Candidate mechanism and exact provisional actions

A new **development** comparison could test whether the public history favors preserving the previous solution or re-deriving one while **retaining the same full prefix**. Both candidate recipes must receive byte-identical public task, initial answer and canonical diagnostic messages, the same receiver/decoder, one continuation opportunity, the same endpoint, and an identical separately versioned final-output contract. The only variable in this candidate contrast is the last user instruction. Provisional text, to be frozen verbatim only in a later complete protocol:

| Recipe | Last user instruction before the identical common output contract |
|---|---|
| `PATCH` | “Use the public diagnostic, if any, to find an error in your previous answer. Preserve its correct behavior and change only what is needed for the full stated task domain. Do not hard-code the public examples. Return one complete solution.” |
| `RETHINK` | “Re-derive a solution from the original task and public diagnostic. Do not assume the previous algorithm is correct; use the previous answer only to avoid witnessed errors. Check the full stated task domain, not only the public examples. Return one complete solution.” |

These are distinct whole-recipe indices, not the old N1/S1 labels. `RETHINK` still sees the previous answer; it is **not** E13a's bare-task FRESH or its context-removing R1. `PATCH` may fail where the old approach is fundamentally wrong, while `RETHINK` may damage an initially correct answer. That possible crossing is the falsifiable reason to test a history-dependent choice; neither direction is asserted from existing data. The exact quoted bytes, shared prefix, output contract, and public-only feature law require a future freeze and source/mock review. The two texts need not have equal token length; actual prompt/completion tokens, execution starts, latency and energy must be measured, and any total-cost claim evaluated separately from the primary quality contrast.

## Advancement gate

Do **not** fit a selector on E12/E13a outcomes or reuse those roots as independent evaluation. First freeze a supported development roster, root/family grouping, public-history feature dictionary, randomized recipe assignment with positive known probabilities, exact receiver/evaluator/source versions and a valid all-assigned endpoint. After new development support, select one competent fixed recipe `b1` and freeze a selector `d` using development families only; if the two strategies show no stable conditional ranking or `d` collapses to `b1`, preserve that negative and do not advance a generator. The separately specified B2-1R controller remains a practical package comparator, not an alternative same-prefix wording arm.

An independent policy trial still needs untouched, exposure-audited sampled families, complete assignment and seed tables, a useful-gain and prospective precision/futility rule, fair information and total-resource contracts, a numerical local cap, and a verified resource lease. The 198-ID MRL-15 convenience frame is not such a family sample; four later-ranked IDs have prior unresolved specification exclusions. This note releases **zero** model/receiver calls, tokens, candidate/reference executions, downloads or paid spend. It used only committed text and immutable reused-data summaries; no numerical simulation or fresh data were generated. Overall milestone completion stays **58%, change 0 percentage points**. Prompt efficacy is unestablished; independent policy validation is absent; the full project is not submission-ready.
