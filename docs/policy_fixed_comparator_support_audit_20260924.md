# LEAD-POLICY-02: the fixed comparator is not yet supported as claimed

Coordinating scientific lead, 24 September 2026. **Read-only source and reused-development-result audit; no new trial or release.** The original target remains an independently evaluated public-history rule for the *next prompt at the same prefix*. This audit checks whether E12's saved arms already supply the “competent fixed continuation” required by the [policy design](independent_prompt_policy_validation_design_20260922.md). They do not. The negative E11/E12/E13a findings remain valid in their stated scope.

The pinned [renderer](../experiments/landmark/diagnostic.py), SHA256 `2a98bccf20cf3fa068790b488be8df4347387ae5ffb1bd7b1bd8b9d49d3a72b2`, gives N1 and S1 the same initial answer and public-diagnostic message before their final instruction. N1 then uses one status-invariant neutral instruction; S1 is a **rule** choosing one of three strings based on the public cases. The saved [E12 diagnostics](../results/e12_dev_v3_20260922T030255Z/B/diagnostics.json), SHA256 `e95d50bae632f73a96094673a03aff9401993c5c3d986086f63c5fe3cf8bd94a`, invoke the S1 public-pass string on nine roots, the recorded-failure string on five, and the incomplete-information string on zero. Therefore S1 supplies a supported *conditional rule* on these development histories, but not outcomes for each of its constituent strings as a **fixed instruction across all statuses**. N1 is the only status-invariant diagnostic-enabled instruction actually assigned across this roster. No comparison among competent fixed same-prefix instruction candidates can be selected from these outcomes.

N0 is status-invariant but omits the diagnostic message from the receiver prefix; it is a different context intervention, not an information-matched next-instruction comparator for N1/S1. In the pinned [E12 analysis](../results/e12_dev_v3_20260922T030255Z/analysis_report.json), SHA256 `ca250a3ea3d5bfe275a202f10b58d3c26a247fba5c63798ee56aa53760eaaf8b`, N0 and N1 each score 20/28 and have per-root means equal to STOP on all fourteen development roots. The saved **hypothetical per-policy** accounting gives N0 two model calls, 448.29 prompt tokens, 85.21 completion tokens and zero public-diagnostic starts per root; N1 gives two calls, 626.86 prompt tokens, 93.43 completion tokens and one public-diagnostic start. These are descriptive realized averages, not population cost estimates or a claim of stochastic dominance. The actual study ran a shared diagnostic for every root; its research expenditure must remain separate from these deployment scenarios. N0 may be a useful *practical* baseline with its own context/cost contract, but inserting it as `b1` silently changes the same-prefix instruction-choice comparison.

**Decision.** Retain N1 as a matched-exposure **mechanism control**, not as an already certified competent fixed policy. Do not use E12 or the proposed N1-versus-status-rule E14 panel to claim a learned selector beats a development-selected best fixed instruction. Before a policy trial, define a status-invariant diagnostic-enabled candidate set whose exact strings are applied across the relevant public-status support on **development** families; predeclare family-weighted selection and tie breaking (including total resource cost), then lock one fixed `b1` before untouched-family evaluation. The learned `d` must choose from the same exact supported recipes at the same prefix. If only N1 is available, the honest estimand is `d` versus that named neutral control, not benefit over a competent selected fixed policy. Keep N0 and the bare-task independent-sampling controller as separately labeled practical comparators, with complete cost and stopping laws. No evaluation root, private grade or partial confirmatory outcome may be used to repair these definitions after the freeze.

This removes a specific false shortcut but does **not** complete the trial freeze: the untouched family frame, source-valid endpoint, selector training, assignment/seed laws, useful-gain/precision/futility analysis and numerical local cap remain unresolved. E14, source renewal and all model collection remain **HOLD**. This audit read committed text/JSON and ran only scalar/count checks: zero new receiver calls or tokens, candidate/reference/benchmark executions, fits, synthetic draws or paid spend. **58%, change 0 percentage points** under the fixed rubric; prompt efficacy is unestablished and the full project is not submission-ready.
